# Wealthsimple 同步 + 每日盈亏日历

本地、免密码的 Wealthsimple 活动记录导入流程,以及首页日历"每天赚/亏多少"的计算方式。

## 一次性准备

```bash
npm install
```

在 Supabase Dashboard → SQL Editor 里整段执行一次 `supabase/schema.sql`(已经建过的表会自动跳过)。
最新加的部分是收盘价表 `stock_prices` / `stock_price_symbols` 和 `import_logs` 的三个新列——没建的话导入仍然能跑,
但日历只能拿实时价/成交价推算,面板上会有黄色提示。

`.env`(或 `.env.local`)里需要:

```bash
VITE_SUPABASE_URL="https://your-project.supabase.co"
SUPABASE_SECRET_KEY="sb_secret_..."      # 或 SUPABASE_SERVICE_ROLE_KEY
```

## 日常用法

```bash
npm run ws:helper
```

保持这个 helper 开着(http://127.0.0.1:8899),首页"同步"面板里的两个按钮就都能用:

- **更新**:打开 Wealthsimple(浏览器 profile 存在 `.local/wealthsimple-browser`,登录/2FA 自己做,脚本只盯着下载),
  下载活动 CSV → 导入 `stock_trades` / `stock_cash` / `daily_transactions` → 同步收盘价 → 写一条 `import_logs`。
- **更新行情**:只同步收盘价,不碰 WS。收盘后(美东 16:10 之后)点一下,当天的盈亏就从"实时价"变成"收盘价"。
  helper 开着的话,页面发现收盘价落后于最近一个交易日时会自动补一次,不用手点。

不想开 helper 也可以手动跑:

```bash
npm run ws:download            # 只下载 + 试跑解析
npm run ws:import -- --file data/wealthsimple/downloads/xxx.csv --apply
npm run prices:sync            # 只同步收盘价
```

## 日历上的每日盈亏是怎么算的

算法在 `src/app/lib/dailyPnl.ts`,前端页面和导入脚本 import 的是同一份文件。每个 ticker + 币种 + 账户,每个交易日一行:

```
当日盈亏 = 收盘持仓 × 当日收盘价 − 开盘持仓 × 前一日收盘价 − 当日买入总额(含手续费) + 当日卖出总额(扣手续费)
```

这一条式子覆盖全部情况:昨天买今天没卖 = 股数 × (今收 − 昨收);昨天买今天卖了 = 卖出额 − 股数 × 昨收;
今天买没卖 = 股数 × 今收 − 买入额;今天买今天卖 = 卖出额 − 买入额;加仓/减仓/多笔自然相加。
一段持仓从开仓到清仓的每日盈亏之和恒等于 FIFO 已实现盈亏(含手续费)。

**不落库**:每日盈亏不存表,每次打开页面都从 `stock_trades + stock_splits + stock_prices` 现算。
所以交易记录一改(WS 同步、网页上增删改),日历立刻跟着变,不存在"快照过期"。原来的 `stock_snapshots` 表已经不用了,可以留着也可以删。

**价格来源优先级**(取"今收"和"昨收"用的是同一个函数,所以数据补到哪一步都不会重复算或漏算):

1. `stock_prices` 里这一天的真实收盘价
2. 只对"今天":页面拉到的实时价(盘中是浮动值,收盘后同步行情就变成最终值,日历上带 `~` 的就是这种)
3. 之前最近一天的收盘价(行情还没同步到这天 / 停牌 / 退市)—— 当天变动记 0,等同步后自动补上
4. 这只票之前最近一笔成交价(雅虎完全没有这只票的数据,比如已到期的期权)

**汇率**:每天的原币种盈亏都用同一个"当前汇率"折算成展示币种,汇率本身的波动不会混进逐日盈亏里。

### 已经考虑到的边界情况

- **成交日归属**:WS 的 `effective_date` 是下单时间,晚 8 点之后挂的单在下一个交易日成交。导入脚本用描述里的
  `executed at YYYY-MM-DD` 作为 `stock_trades.date`(日历归属日),`ts` 保留真实下单时间(FIFO 撮合按它排序)。
  网页上手动录入的成交,美东 20:00 之后按次日算。
- **同一只票两个账户**:分别算,明细里带 TFSA / NR 标签,汇总按币种。
- **超卖**(记录缺失导致持仓为负):照常算,明细里标 ⚠ 提示"可能缺少买入记录"。
- **周末/假日**:没有 K 线的日子不出现;周一的"昨收"沿用周五收盘价,不算临时值。
- **拆股/合股/换股**:`stock_prices` 存的是"当时的原始收盘价"。雅虎返回的历史价通常按后来的拆股回调过了,
  同步脚本用雅虎给的拆股事件乘回去;但雅虎并不是每只票都回调(实测 IESC 有事件、价格却没回调),
  所以脚本会拿你自己的成交价校准:哪种口径让"成交当天收盘价 ÷ 成交价"最接近 1 就用哪种。
  校准后仍对不上的会在同步日志里标"需核对"。持仓穿越拆股日的,仍然要在网页上录一条拆股记录(`stock_splits`)让股数对上。
- **期权**:WS 导出的 OCC 代码(`TSLA  260706C00405000`)价格是每张合约总价,乘数 1;手输的 `TSLA Jul 27 $410 Call`
  是每股权利金,乘数 100。到期的期权雅虎没有历史价,按成交价兜底,盈亏全部落在卖出那天。
- **CAD 标的**:先试 `.TO` 再 `.NE`(CDR 大多在 `.TO` 有数据),要求雅虎标的币种是 CAD。
- **雅虎没有的票**:标 `not_found`,还持有的每天重试一次,已清仓的不再试。
- **收盘后头几个小时**:雅虎当天那根日 K 的 close 常常还是空的,脚本改用 `meta.regularMarketPrice`(常规时段正式收盘价,只在 regularMarketTime 已到收盘时刻才用)。同步状态记的是真正拿到的最后一根 K 线,所以当天没拿到的话下次会自动再试。

### 同步日志

每次 `--apply` 导入都会在 `import_logs` 写一条:新增/更新了多少笔、涉及哪些日期、每一笔成交的变动明细
(`trade_changes`),以及最关键的 **日历变动对比**(`pnl_diff`):同步前后各算一遍每日盈亏,列出哪几天新增、
哪几天修改(从多少变到多少)、哪几天消失,并标明原因是交易变动还是行情更新。首页"同步"面板下面能直接看。

网页上增删改交易之后,股票记录页顶部也会弹同样格式的"日历变动"提示。

## 其他

- 脚本不保存 Wealthsimple 密码和 2FA。
- Wealthsimple 改了 CSV 表头的话,`scripts/wealthsimple/import-csv.mjs` 里的字段映射要跟着调。
- 分红/利息目前当作现金入账(`stock_cash` deposit),不计入股票盈亏。
- 想强制重拉某只票的收盘价:`npm run prices:sync -- --refetch TICKER|USD`。
